# Experiment design lab — clearance markdowns, a natural experiment

**What it is:** an A/B-test-quality experiment design and analysis on a real-shaped business
dataset, including a measured power analysis and a difference-in-differences estimate checked
against a known truth.

**Stack:** Python · pandas · NumPy · SciPy · DiD · cluster bootstrap · Jupyter

**No deployment** — this is a statistical artifact, and its deliverable is a design document, a
notebook and a decision, not an app.

---

## The problem

Four SKUs in a fictional Mexican import group carry a clearance markdown during March, September
and November. The owner has to decide whether to keep selling them at the discount, withdraw them,
or cut deeper.

- **Keep selling:** cash now, but each unit may destroy margin.
- **Withdraw:** stops the loss, but locks up capital already committed.
- **Cut deeper:** clears stock faster — *if* demand responds to price.

That last option is the one that needs evidence, and it is the one this data cannot supply. Why it
cannot is the most important result in this project.

## Data

| | |
| --- | --- |
| **Source** | `holding-360`'s published ground truth — a **synthetic** three-company import group |
| **Provenance** | Generated by that project from a single seed; deterministic and reproducible |
| **Panel** | 3,911 bringToMX customer-invoice lines, 44 SKUs, 18 months (2025-01 → 2026-06) |
| **Treatment** | 4 SKUs with a clearance markdown × 3 calendar months (Mar, Sep, Nov) |
| **Control** | The 40 SKUs that never carry a markdown |
| **Licence** | Synthetic — no real company, customer, invoice or exchange rate is involved |

**Every number in this repository describes a fictional business.** Nothing here is client work.

## Approach

1. **Check the treatment before measuring anything.** Every discounted line must sit in a treated SKU
   *and* a treated month. Measured: **27 discounted lines, 0 mislabelled.**
2. **Build the panel from sales only.** The first version included supplier invoices — costs in USD
   and CNY, converted at transaction-date rates — which injected cost variability that does not exist
   in the sales data. Excluded, and asserted in the tests.
3. **Estimate the effect two ways.** The naive own-change and a difference-in-differences, both
   compared against the **known true effect**, which is computable because the world is synthetic.
4. **Test the parallel-trends assumption instead of assuming it.** A fixed-weight decomposition of
   the control group shows whether its movement is price/cost or product mix. A placebo DiD on a fake
   treatment bounds what the design can manufacture out of nothing.
5. **Compute the power, then check the formula by simulation.** The closed form and the simulated
   detection rate must agree; both are reported.

## Results

| Estimate | Value (MXN/unit) | Error vs truth |
| --- | --- | --- |
| Naive own-change (treated) | **−1,847.05** | +53.32 (**2.8%**) |
| Difference-in-differences | **−1,870.71** | +29.66 (**1.6%**) |
| **Known true effect (ATT)** | **−1,900.37** | — |

DiD cluster-bootstrap 95% CI (resampling whole SKUs): **[−2,468.92, −1,296.04]** — it covers the truth.
Welch's t on treated lines: **t = −6.90, p = 6.0e−08**.

### The finding that matters

**The control group's month-to-month movement is 100% product mix.**

| Control-group monthly mean unit margin | sd | range |
| --- | --- | --- |
| Raw mean | 72.51 | 269.33 |
| **Fixed-weight (mix removed)** | **0.00** | **0.00** |

Price and landed cost are constant per SKU, so a mix-neutral control series is *exactly* flat. There
is **no time-varying common shock for DiD to remove** — the second difference corrects a composition
artefact worth **MXN 23.66** against an effect of **MXN 1,900.37**. The placebo DiD returns
**MXN 25.71**, or **1.4%** of the real estimate: the same magnitude, as it should be.

So the sophisticated estimator is closer to the truth, and the reason it is closer is much smaller
than it looks.

### The power analysis

| To detect a change in unit margin | Δ (MXN) | n per arm | Formula power / simulated |
| --- | --- | --- | --- |
| 5% | 71.43 | **2,777 lines** | 0.80 / **0.80** |
| 10% | 142.86 | **695 lines** | 0.80 / **0.81** |
| 15% | 214.30 | **309 lines** | 0.80 / **0.80** |

The formula and the simulation agree, so the sample-size arithmetic is trustworthy. The retrospective
study has **27** treated lines — but the effect is so large that even that is plenty.

| To detect a lift in units | Δ (units) | SKU-months per arm |
| --- | --- | --- |
| 5% | 0.68 | **6,805** |
| 10% | 1.37 | **1,702** |
| 20% | 2.74 | **426** |
| 30% | 4.10 | **190** |

Available treated SKU-months: **70**.

### The honest conclusion

**The generator allocates units from family volumes, seasonality and SKU velocity. Price never enters
that function.** The markdown's effect on volume is exactly zero by construction — so no test can
find a demand response here, and running one anyway would produce a null that reads like evidence
while being arithmetic.

> The design answers the question that is true by arithmetic to within 2%, and **cannot** answer the
> question a business would pay for. Saying so is the result.

**Decision:** the markdown SKUs are a **cost** decision, not an experiment decision. Withdrawal is
justified by the margin arithmetic alone. A real demand question needs a prospective test at the
sample sizes above, or a generator that models price elasticity.

## How to run

```bash
git clone <this repo> && cd experiment-design-lab
python -m pip install -r requirements.txt

python src/main.py                    # the full analysis -> reports/results.json
python -m pytest tests/ -q            # 14 tests
python scripts/explore_markdown.py    # the read-only feasibility probe
python scripts/build_notebook.py      # rebuild and execute the notebook
```

**Requires** the sibling `holding-360` project checked out alongside this one, because the panel is
built from its published ground truth rather than from a copy.

## What I would do next

1. **Run it prospectively.** A live price change with the sample size from the power table is the only
   design that can answer the demand question.
2. **Add elasticity to the world.** The generator should contain the mechanism the business question
   depends on; a dataset that cannot express the answer cannot test it.
3. **Get more treated clusters.** Four treated SKUs is the binding constraint on inference;
   the bootstrap is honest about it, but more clusters would tighten the interval.

## Limitations

- **Synthetic data.** The known truth is only available because the world is generated. In a real
  setting the estimator check in §2 could not be run, and the parallel-trends verdict would rest on
  pre-period testing this design cannot support with four clusters.
- **No price elasticity exists**, so the demand hypothesis is untestable here. This is a property of
  the data, not a gap in the analysis.
- **Tiny treated arm.** 27 discounted lines across 4 SKUs and 4 treated months. The cluster bootstrap
  reflects this; a line-level confidence interval would be badly overconfident.
- **The markdown is a deterministic rule**, so the treatment effect is mechanical. This makes the
  estimate clean and the exercise less informative than a behavioural effect would be.
- **No multiple-comparison correction is needed** because exactly one outcome and one design are used.
  Adding outcomes would require a correction this analysis does not apply.
